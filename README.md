## Docker template to run AI locally
The main goal is to test and use new AI models that show up every day for "free", without giving the AI full access to your machine. That is my main goal with this project.


## 🏗️ Project Structure

The environment is set up with two main files: `Dockerfile` and `docker-compose.yml`. Below is how each part works.

### 📄 Dockerfile

The `Dockerfile` is the recipe for how our container image is built.

- `FROM node:20-slim`: Sets the base image. Docker pulls this lean (slim) Node.js version (20) from Docker Hub to be the foundation of our container.
- `RUN apt-get update && apt-get install ...`: When the container is built from the Node image, this command runs in the Debian (base system) terminal to install essential tools the AI may need, such as `git`, `bash` and `curl`.
- `WORKDIR /workspace`: Creates a virtual work area (a directory) inside the container. This is where commands run by default, and you can change it to wherever you want them to run.
- `RUN npm install -g AI-NAME`: Uses the Node package manager (`npm`) to install the AI of your choice globally inside the container.
- `ENTRYPOINT ["freebuff"]`: The main entry point. As soon as the container starts, it automatically runs Freebuff (opening its login screen/interface).

### 🐙 Docker Compose

The `docker-compose.yml` file orchestrates how the container runs, making it easier to start.

- `services`: Defines the services that run when we execute `docker compose up` or `docker compose run`.
- `freebuff`: The name of our service.
    - `build.context: .`: Tells Docker to build the image using the current directory (`.`) as the base.
    - `dockerfile: Dockerfile`: Points to the file used for the build.
    - `container_name: freebuff_cli`: Gives the container a fixed, friendly name instead of a random one generated by Docker.
    - `stdin_open: true` and `tty: true`: Keep the interactive terminal open. This is **essential** for CLI (command line) tools like Freebuff to work and accept our commands.
    - `volumes`: Maps data between the local machine (host) and the container.
        - `- /home/example/project:/workspace`: Connects the `/home/kauezao` root folder on the machine to the container's `/workspace` directory. *(Note: since my goal is not to expose the whole OS, you can map only the specific project folder instead of your entire home, which improves security.)*
    - `working_dir: /workspace`: Makes the container start in this folder.
